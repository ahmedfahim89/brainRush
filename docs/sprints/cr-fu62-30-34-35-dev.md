## FU-62 — built-in name guard collapses whitespace

`save_category_name()` now turns every run of whitespace (`preg_replace('/\s+/u', ' ', ...)`, Unicode-aware, so no-break and ideographic spaces count too) into one space and trims the result. It does this before comparing with `MIX_NAME`, and stores the name in that form (create and rename). So "Kilo  Meshakkal", "KILO \t MESHAKKAL" and "Kilo&nbsp;&nbsp;Meshakkal" give the same 409 as "Kilo Meshakkal". "Kilo Meshakkal2" is still allowed. The duplicate-name 409 also compares the collapsed name, so "TEST   FU62 Cat" clashes with "TEST FU62 Cat".

- A name made only of Unicode spaces that `trim()` keeps (for example a no-break space) is now 400 "Name is required" instead of being stored blank.
- The Arabic name is unchanged. `save_category_name()` never touched it, so it is not collapsed.
- Admin client: no change needed. It sends trimmed names and redraws the list from the server. The only cosmetic gap is that the success line echoes the typed name ("Category "A  B" added."), and HTML collapses those spaces on screen anyway.

## FU-30 — Daily #N from a launch-date constant

`const DAILY_LAUNCH_DATE = '2026-11-02';` sits next to `DAILY_QUESTIONS` in `api/daily.php`. `daily_number()` now counts UTC calendar days from that date, plus 1, with a floor of #1. It no longer reads the DB, so deleting questions or rows can't shift the number, and every database gives the same #N for a date. The date comes from FU-29/the brief, and it matches live #10 on 2026-11-11.

## FU-34 — Golden Goal polish

1. When everyone is marked and the top is still tied, the big button reads **"Next round"** (AR **"الجولة التالية"**). The i18n key `final.continue` is renamed to `final.nextRound`; it was only used there.
2. In the app, Back on a Golden Goal question where everyone is marked and the top is still tied now asks first with `final.leaveTied`:
   - EN: "Stop Golden Goal and show the results? The tie stands."
   - AR: "إيقاف الهدف الذهبي وعرض النتائج؟ يبقى التعادل قائمًا."

   OK opens Results with the tie (`finishFinal()`, as before). Cancel stays on the question, and the existing popstate code re-arms the Back entry. Back with someone unmarked keeps its old confirm. Back with no tie left still goes to Results with no confirm. The offer/bets Back cases (D-52 a) are untouched. There is no rule change and no saved-game change.

## FU-35 — Golden Goal draw excludes Swap questions

A used cell closed after a Swap now also saves the swapped-in question's id (`used[key].swap.id`). It is optional in `isValidUsedSwap()`: a positive integer, or missing in saves made before this change. The new `swapQuestionIds(g)` collects these ids, plus the open question's Swap (if any). The Golden Goal draw sends `exclude = board ids + Swap ids + final.usedIds` to the existing `questions.php?random=1`. There is no server change.

## Limitations

- Games saved before this change have no `swap.id` on cells that were already closed, so those Swap questions are not excluded in that game (only a game in progress across the deploy).
- The Swap helper's own draw still excludes only the board's ids, not earlier Swap questions. That is out of FU-35's scope; one Swap per contestant and the played list make a repeat unlikely.
- Local #N now equals live #N for the same date, so local numbers before 2026-11-02 all read #1.
